# Feature Design - Team Invite Approval

This scenario proves that `/feature-design` behaves like a design-stage skill instead of collapsing into:
- a broad `/feature-audit`
- a narrow `/pressure-test`
- or immediate implementation

The model should:
- compare at least two viable approaches
- recommend one direction
- write a concrete design memo artifact
- cover approval states, seat billing, expiry, auditability, and related surfaces

The model should write only `artifacts/team-invite-approval-design.md`.
